## 关键差异总结

1. **字段命名完全不同**：线上是全称（`date`/`name`/`nameOrig`/`country`/`age`/`fields`/`identity`/`source`），全表是缩写（`d`/`n`/`no`/`c`/`a`/`f`/`i`/`s`）。接入时必须做一层映射。
2. **内容深度差距大**：线上有 6 个全表没有的字段（`summary`/`bio`/`facts`/`obit`/`portrait`/`verified`），这些正是「精选档案」的价值所在。
3. **语言差距**：线上 `identity` 是中文，`name` 100% 中文；全表 `i` 多为英文，`n` 仅 6.9% 是真中文。
4. **共有字段取值一致**：`fields` 都是同一套 11 个中文领域，`country` 都是中文分号分隔，`id`/`date` 格式相同——这是接入的有利基础。

## 接入时的转换规则

若把全表记录接入线上页面，需按如下映射（伪代码）：

```js
{
  id: x.id,
  date: x.d,
  name: x.n,
  nameOrig: x.no || "",
  country: x.c || "",
  age: x.a || 0,
  fields: x.f || [],
  identity: x.i || "",
  summary: "",      // 全表无
  bio: "",          // 全表无
  facts: [],        // 全表无
  obit: null,       // 全表无
  portrait: null,   // 全表无 → 页面自动回退首字方块
  source: x.s || (x.w ? "维基百科" : ""),
  region: "",
  verified: "auto", // 全表为自动抓取，与线上 "demo" 区分
}
```

**注意**：`fields` 与 `country` 取值已统一，无需再转换；`fields` 为空的记录（21.6%）在筛选时应归入「其他」。
